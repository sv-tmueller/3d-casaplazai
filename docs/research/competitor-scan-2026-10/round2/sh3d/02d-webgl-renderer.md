## 1. Summary (5 bullets)

- **The 3D view is a WebGL 1 renderer written in-house on a Java3D-shaped scene graph.** `HTMLCanvas3D` owns one `webgl` context on `#home-3D-view`, one shader program (a **per-fragment Phong** shader looping over up to 16 directional lights), one texture list and a flat "draw item" list; **there is no `drawElements`, no index buffer, no VAO and not a single `getExtension` call** — every geometry is drawn with `gl.drawArrays` over an expanded, un-indexed `Float32Array`. Measured live on the Studio demo: 18 277 draws, **0** `drawElements`, average **57 triangles per draw**. **OBSERVED**
- **The scene graph is a real Java3D port**: `Node3D` / `Group3D` / `BranchGroup3D` / `TransformGroup3D` / `Link3D` (instancing) / `Shape3D` / `Appearance3D` / `Background3D` / `Light3D`, plus an `Object3DBranchFactory` mapping each home model object (`Wall`, `Room`, `HomePieceOfFurniture`, `Polyline`, `DimensionLine`, `Label`) to a 3D branch (`Wall3D`, `Room3D`, `HomePieceOfFurniture3D`, …). Geometry is produced by *Java2D ported code* (`java.awt.geom.Area` boolean ops, `PathIterator`, `Line2D.ptLineDistSq`) and then handed to `GeometryInfo3D` — the same Java3D `GeometryInfo` API. **OBSERVED**
- **Model loading is a chain-of-responsibility over three in-house parsers** — `OBJLoader` (extension `obj`, also parses `.mtl`), `DAELoader` (`.dae`, a SAX/COLLADA parser with `1.4` version gate, `unit@meter` scaling, skins/controllers), `Max3DSLoader` (`.3ds`, chunk-based, material groups, smoothing groups, node hierarchy, pivot/track tags). Assets arrive as `jar:…zip!/entry` and are unzipped by JSZip; the loader tries loaders in order and falls through on "Unsupported 3D format". **There is no `.kmz` loader despite the desktop manual mentioning KMZ.** **OBSERVED / DOCUMENTED**
- **Triangulation is a full ear-clipping + reflex-vertex + degenerate-handling port of Sun's `Triangulator`**, driven from `GeometryInfo3D.getIndexedGeometryArray()` for `POLYGON_ARRAY`; `QUAD_ARRAY` is split to two triangles by hand and `TRIANGLE_STRIP/FAN` by index arithmetic. Normals are either supplied or generated with a **crease-angle smoothing pass** (default 44°, walls/rooms override it). **OBSERVED**
- **The app's own performance measures are: (a) an adaptive texture-download concurrency governor driven by `requestAnimationFrame` jank ("jerk monitor": starts at 6 concurrent image loads, floor 2, ceiling 12, lower on Safari), (b) a manual dirty-flag `repaint()` coalesced by `requestAnimationFrame` with no continuous render loop — measured live, 4 s of idle after settling produced exactly **0** additional draws, (c) a colour-coded ID framebuffer for picking (rendered once, then `readPixels` on demand), (d) geometry caching/sharing keyed by model URL with `Link3D` instancing, (e) `getFramesPerSecond()` **but no UI that displays it**, and (f) an offscreen 3D renderer that rasterises furniture thumbnails into the 2D plan instead of loading icon images.** A furnished demo home costs ≈0.2 MiB in 33 separate `.zip` requests and ≈13.5 s to build on a CPU rasteriser; a camera drag then re-issues ~32 000 draws because nothing is batched. **OBSERVED**

### 2.2 HTMLCanvas3D — the WebGL renderer

**Context creation.** `function HTMLCanvas3D(canvasOrId, offscreen)` resolves the canvas by id or element, calls `getContext("webgl")`, falls back to `getContext("experimental-webgl")`, throws the string `"No WebGL"` otherwise. `offscreen=true` suppresses the `requestAnimationFrame` repaint path so an offscreen canvas can be rendered on demand. Fields: `textures[]`, `sharedGeometries[]`, `sceneGeometries[]`, `backgroundGeometries[]`, `lights[]`, `fieldOfView` (default 45°), `frontClipDistance` 0.1, `backClipDistance` 100, `projectionPolicy` = `PERSPECTIVE_PROJECTION`. There are two projection policies: perspective (`mat4.perspective`) and `PARALLEL_PROJECTION` (`mat4.ortho(-1,1,-1,1,0.001,1)`) — the latter is used for the automatic plan-view and the offscreen furniture-thumbnail renderer. **OBSERVED** (1724503–1735500)

**One shader program for everything.** Vertex shader attributes: `vertexPosition` (vec3), `vertexNormal` (vec3), `vertexTextureCoord` (vec2). Uniforms: `modelViewTransform`, `projectionTransform`, `textureCoordinatesGenerated` (bool), `planeS`/`planeT` (vec4, for **procedurally generated texture coordinates** — a plane projection instead of per-vertex UVs), `textureCoordTransform` (mat3), `normalTransform` (mat3), `ignoreNormal`, `backFaceNormalFlip`, `lightingEnabled`, `useTextures`. Fragment shader uniforms: `vertexDiffuseColor`, `vertexSpecularColor`, `shininess`, `sampler`, `alpha`, `useTextures`, `lightingEnabled`, `ambientColor`, `directionalLightCount`, `lightDirections[MAX_DIRECTIONAL_LIGHT]`, `directionalLightColors[MAX_DIRECTIONAL_LIGHT]`. `HTMLCanvas3D.MAX_DIRECTIONAL_LIGHT = 16`. **OBSERVED**

The lighting is **per-fragment (Phong shading over interpolated normals), not per-vertex/ Gouraud**: the vertex shader only transforms the normal into `varTransformedNormal`; the fragment shader then loops over `directionalLightCount` lights, computes `max(dot(varTransformedNormal, lightDirections[i]), 0)` and a `reflect(...)` specular term per pixel, accumulating `lightWeight` from `ambientColor` and `vertexDiffuseColor`. Specular is gated on a nonzero `vertexSpecularColor` and on `length(eyeDirection) <= 1.0001`, i.e. specular is skipped in an orthographic/parallel projection. `precision mediump float` (WebGL 1 / GLSL ES 1.00, no `#version` directive). **OBSERVED** (fragment source immediately after `HTMLCanvas3D`'s `createShader(FRAGMENT_SHADER, …)`)

**Capabilities actually required**: WebGL 1 only. No `getExtension` call at all in `HTMLCanvas3D` (grep of the whole bundle finds `getContext("webgl")` ×2, `getContext("experimental-webgl")` ×2, one `"No WebGL"`, and **zero** `getExtension(` occurrences in the 3D path). So no `OES_element_index_uint`, no VAO extension, no float textures, no instancing extension — and consequently no 32-bit indices, which is precisely why all geometry is de-indexed. **OBSERVED**

**WebGL feature detection is a throwaway canvas, not a context attribute.** `PlanComponent.initStatics` creates `document.createElement("canvas")` (no id), calls `getContext("webgl")` then `"experimental-webgl"`, and sets `PlanComponent.WEBGL_AVAILABLE` — this is the app's only capability gate, and it decides whether the 3D view is offered at all. In the live run the *first* `getContext` the instrumentation saw was on an **id-less canvas** and it was already `contextKind: "webgl"` — i.e. the very first context in the page belongs to this probe, and the main `#home-3D-view` context comes later. So the app performs **no version or extension negotiation** beyond "does a WebGL 1 context exist". **OBSERVED** (`evidence/live-webgl.json`, `raw.canvasId === null`, `raw.contextKind === "webgl"`; source: `PlanComponent.initStatics`)

**Geometry upload.** `prepareBuffer(vertices, indices)` walks the index list, copies each referenced vertex into a flat `Float32Array` of size `indexCount * components`, and uploads with `bufferData(ARRAY_BUFFER, …, STATIC_DRAW)`. `prepareGeometry(shape, appearance, texture, shapeNode, sharedGeometries, geometryItems, backgroundGeometries, background, links, transform)` builds one draw item per geometry with `vertexCount = geometry.vertexIndices.length`, `mode = TRIANGLES` for `IndexedTriangleArray3D` and `LINES` for `IndexedLineArray3D`. It computes the geometry centre from the shape bounding box and caches the item in `sharedGeometries` when the shape is **not** `ALLOW_GEOMETRY_WRITE`, incrementing `referenceCount` on reuse — i.e. **the same model loaded twice shares GPU buffers**; mutations invalidate the cache via a `GEOMETRY` property-change listener. **OBSERVED** (1739897–1741951)

**Draw loop.** `drawScene()`:
1. `gl.viewport(0,0,viewportWidth,viewportHeight)`; reads background colour from the canvas's computed style (falls back to `style.backgroundColor`), teases `rgb(...)`/`rgba(...)` apart with string ops, `clearColor` + `clear(COLOR|DEPTH)`.
2. Computes direction of each `DirectionalLight3D` by transforming its direction by the inverse view platform transform, negating it, packing flat arrays for `lightDirections` and `directionalLightColors`; `AmbientLight3D` colours are summed into `vec3 b` (ambient). Light count is clamped to `MAX_DIRECTIONAL_LIGHT` with zero-fill.
3. Perspective matrix for the **background pass**: `w = 2*atan(viewportHeight/viewportWidth * tan(fieldOfView/2))`, then `mat4.perspective(n, w, aspect, 0.001, 1)` (or `mat4.ortho(n,-1,1,-1,1,0.001,1)` under `PARALLEL_PROJECTION`). Note the fixed near/far of **0.001 and 1.0**: the background is a **unit-radius hemisphere** drawn with the camera translation removed (`m = clone(viewPlatformTransform); m[12]=m[13]=m[14]=0; p = invert(m)`), so this is not the scene's camera. After the background is drawn the depth buffer is cleared and the projection is recomputed by `getVirtualWorldToImageTransform(n)`, which **does** use `frontClipDistance`/`backClipDistance` for the real scene.
4. **Background pass**: draws `backgroundGeometries` with the camera translation removed (so the sky/ground stay centred on the camera), then `clear(DEPTH)`.
5. **Opaque pass**: iterates `sceneGeometries`; an item is "opaque" iff `transparency === undefined || transparency === 1` and it has no texture whose image is `transparent`; those are drawn immediately with the depth test on. Fully transparent items (`transparency === 0`) are skipped entirely — a free cull for invisible glass and for models whose materials are marked 100 % transparent.
6. **Transparent pass**: everything else with `transparency > 0` is collected, `enable(BLEND)` with `blendFunc(ONE, ONE_MINUS_SRC_ALPHA)`, each item's centre transformed into view space to get a `zOrder`, and the list **sorted by `zOrder` ascending** before being drawn back-to-front. Note the draw-item field is **inverted**: `transparency = 1 - appearance.getTransparency()`, so the renderer's `1` means opaque and `0` means fully transparent; an item with `transparency === 0` is **silently dropped** (neither opaque nor `> 0`), i.e. fully transparent objects are free. **OBSERVED**
7. Frame-rate bookkeeping (see 2.5).

**Per-draw state changes** (`drawGeometry`): cull-face mode (`CULL_NONE`/`CULL_BACK`/`CULL_FRONT`, default `CULL_BACK`), `modelViewTransform`, `lightingEnabled`, `ambientColor` (multiplied by the ambient light colour, and forced to 0 when a texture is present), `shininess`, `vertexSpecularColor`, `normalTransform` via `mat3.fromMat4`, `ignoreNormal` forced true for `LINES`, `backFaceNormalFlip`, texture binding / `useTextures` / `planeS`/`planeT`/`textureCoordTransform`, `vertexDiffuseColor`, then `drawArrays(mode, 0, vertexCount)`. Every uniform write is guarded by an `exactEquals` comparison against a cached "shader*" value — a manual **redundant-state-elimination cache**. **OBSERVED**

**Repaint model.** There is **no continuous animation loop**. `repaint()` sets `canvasNeededRepaint` and, for a non-offscreen canvas, schedules one `requestAnimationFrame` that calls `drawScene()` once and clears the flag; `reset of pickingFrameBufferNeededRepaint = true` means the next pick re-renders the ID buffer. `setScene` runs `prepareScene` on a `setTimeout(…, 0)` and calls `drawScene()` — i.e. scene binding is deferred to keep the UI thread responsive, and `prepareScene` reports progress through the `ModelLoader.BINDING_MODEL` callback every 10 %. **OBSERVED**

**Picking.** `getClosestShapeAt(clientX, clientY)` lazily builds a framebuffer whose colour attachment is a texture sized to the canvas (rounded up to a power of two by `Appearance3D.getNextHighestPowerOfTwo`) plus a `DEPTH_COMPONENT16` renderbuffer. When the pick buffer is dirty it re-renders all `sceneGeometries` that are `visible && node.isPickable()`, writing the geometry's **index in the array** as an RGB colour (`((i>>>16)&255)/255, …`), temporarily overwriting `diffuseColor`, with lighting, textures and blending off. It then `readPixels` the **whole** buffer into a `Uint8Array` and indexes it from the client coordinates (with `canvas.getBoundingClientRect()` for the mapping and a Y flip). White `16777215` means "nothing". **OBSERVED** (1758199–1761300)

**Texture handling.** `prepareTexture(image)` de-duplicates by `image.url` in `textures[]`. `bindTextureAndRepaint` **resizes any non-power-of-two image (unless transparent and `resizeTransparentTextures` is disabled) to the next power of two by drawing it into a scratch 2D canvas and round-tripping through `toDataURL()`/`new Image()`** — this is the app's NPOT workaround instead of the `CLAMP_TO_EDGE` route. `bindTexture` sets `UNPACK_FLIP_Y_WEBGL` and `UNPACK_PREMULTIPLY_ALPHA_WEBGL` true, uploads RGBA/UNSIGNED_BYTE, uses `LINEAR` mag filter, and `LINEAR_MIPMAP_NEAREST` + `generateMipmap` **only when both dimensions are powers of two**, else `LINEAR` min filter + `CLAMP_TO_EDGE` wrap. `errorTexture` is a 1×1 opaque red texture created in the constructor. `clear()` deletes all textures, buffers, the picking framebuffer and detaches shaders. **OBSERVED** (1743972–1745338, 1745338–1746666)

**Textures are shared across the 2D and 3D views** through one `TextureManager.getInstance()` singleton (`loadedTextureImages` keyed by URL, `loadingTextureObservers` for in-flight joins). **OBSERVED** (1852815 ff.)

**Procedural sky, ground and lighting.** `createSceneTree` builds `Group3D{ background, ground, homeTree, lights }`. The sky is a **unit-radius half-hemisphere** (`createHalfSphereGeometry(true)`) with a 4-vertex ground disc lid; the ground itself is a single large quad `createGroundNode(-50000,-50000,100000,100000)` that, if the home has a `structure` model, is replaced by that model. `createLights` always adds exactly **four directional lights + one ambient light**, not one light per furniture light: directions `(1.5,-0.8,-1)`, `(-1.5,-0.8,-1)`, `(0,-0.8,1)`, `(0,1,0)` at colour `(0.9,0.9,0.9)` (the last `0.7`) plus ambient `(0.2,0.2,0.2)`. A furniture `HomeLight`'s own `<lightSource>` list is **not** turned into scene lights; instead the shapes named `sweethome3d_light*` are hidden unless the light is selected (`ModelManager.LIGHT_SHAPE_PREFIX` in `setVisible`), so the "lamp" geometry is drawn but its bulb is only shown when selected. Light colour is modulated from `HomeEnvironment.LIGHT_COLOR` by multiplying each default channel. **OBSERVED** (1891703 ff., 1939300 ff.)

### 2.3 Model loading: OBJ / DAE / 3DS

**Loading entry point.** `ModelManager.prototype.load(urlContent, synchronous, observer)` iterates `this.modelLoaders = [new OBJLoader(), new DAELoader(), new Max3DSLoader()]`. Each loader's `load()` is called in turn; on `modelError` (or on `getBounds(group).isEmpty()`) it advances `modelLoaderIndex` and tries the next; when all fail it reports `"Unsupported 3D format"`. So **the extension does not select the parser at the top level — every parser tries the bytes and the first one producing non-empty bounds wins.** A per-URL `loadedModelNodes` cache and a `loadingModelObservers` join map mean a model URL is downloaded and parsed once and cloned per instance (`cloneNode` shares `Link3D` shared groups). **OBSERVED** (1847445–1852600)

**ZIP containment.** URLs shaped `jar:<zipUrl>!/<entry>` are unpacked with `ZIPTools.getZIP` + JSZip. If the URL has no entry, the loader scans the archive for the first member whose name matches `.<ext>$` (case-insensitive); if the archive is empty it reports `"Empty file"`. Textures referenced from `.mtl`/`.dae` are extracted from the same ZIP, base64-encoded into a `data:` URL for an `Image`, and transparency is sniffed from the raw bytes (`ZIPTools.isTransparentImage`). A loader-level guard serialises parsing through `parserBusy` / `waitingParsedEntries` and yields with `setTimeout(…, 0)` between entries so a multi-model ZIP does not block the UI thread. Progress is reported as `READING_MODEL → PARSING_MODEL → BUILDING_MODEL → BINDING_MODEL` with a percentage. **OBSERVED** (1769915–1775000)

**OBJ/MTL parser (`OBJLoader`, extension `obj`).** A hand-written line scanner over the raw bytes: `v`/`vt`/`vn`/`f`/`g`/`o`/`s`/`usemtl`/`mtllib`; face tokens are `v`, `v/vt`, `v//vn`, `v/vt/vn` and are stored as index triples. It keeps a `OBJGroup` list, tracks `smooth` (smoothing) flags and builds per-face "OBJFace" objects; faces are grouped into geometry runs only while **appearance, smoothing flag and normal-presence are unchanged**, i.e. it already batches compatible faces. `.mtl` files are fetched and parsed for `Ka`, `Kd`, `Ks`, `Ns` (clamped 1–128), `d` (→ `transparency = 1-d`), `illum` (→ `illumination`) and `map_Kd` (diffuse map, kept as `imageEntryName` to be resolved from the ZIP after the scene is built). `OBJLoader.defaultAppearances` is a lazily built default material (`Ka/Kd/Ks 0.5`, `Ns 60`). **OBSERVED**

**DAE/COLLADA parser (`DAELoader`, extension `dae`).** Delegates to a SAX parser (`SAXParser` + `DefaultHandler` from `jsXmlSaxParser.min.js`) and builds a full handler state machine: `COLLADA@version` must start with `1.4`; `asset/unit@meter` sets `meterScale`; it tracks `library_images`, `library_materials`/`instance_effect`, `library_effects` (`profile_COMMON`, `newparam`, `surface type="2D"`, `sampler2D`), `library_geometries` (sources, positions, normals, texture coords, `float_array` accessors and **accessor strides**, `vertices`, primitives as `triangles`/`polylines`/`polygons` with `<p>` index runs and `<holes>`), `library_nodes`, `library_visual_scenes`, node instantiation and `library_controllers` (`controller`/`skin` — the changelog explicitly mentions MakeHuman skin import). Appearances are built per effect (ambient/diffuse/specular/shininess/transparency), `double_sided`/`<extra>` techniques set `cullFace`, and materials are attached to the geometry by `material` id. **OBSERVED** (1796351 ff.)

**MAX-3DS parser (`Max3DSLoader`, extension `3ds`).** A chunk reader with a large table of 3DS chunk constants (`M3DMAGIC`, `MLIBMAGIC`, `M3D_VERSION`, `COLOR_*`, `PERCENTAGE_*`, `EDITOR_DATA`, `MASTER_SCALE`, `MATERIAL_ENTRY` with `MATERIAL_NAME/AMBIENT/DIFFUSE/SPECULAR/SHININESS/TRANSPARENCY/TWO_SIDED/TEXMAP/MAPNAME`, `TRIANGLE_MESH_OBJECT`, `POINT_ARRAY`, `FACE_ARRAY`, `FACE_MATERIAL_GROUP`, `SMOOTHING_GROUP`, `MESH_MATRIX`, `MESH_COLOR`, `TEXTURE_COORDINATES`, `KEY_FRAMER_DATA`, `OBJECT_NODE_TAG`, `NODE_ID`, `NODE_HIERARCHY`, `PIVOT`, `POSITION/ROTATION/SCALE_TRACK_TAG`, `TRACK_KEY_USE_TENS/CONT/BIAS/EASE_TO/EASE_FROM`). It has a default appearance (`ambient 0.2`, `diffuse 0.7102/0.7020/0.6531`, `shininess 128`), a `Mesh3DSSharedVertex` linked list to weld shared vertices, a **node/pivot hierarchy** builder (so 3DS groups become `TransformGroup3D`s with pivots applied) and material-group splitting. The changelog records bug fixes in this parser in 7.5.x ("Knotenhierarchie im 3DS-Formatmanagement behoben", "Standardfarbe des Effekts im DAE-Format behoben"), confirming it is an actively maintained in-house parser rather than a library. **OBSERVED / DOCUMENTED**

**Post-load model surgery (`ModelManager`).** After parsing, three passes run on the scene graph, all keyed off **shape-name prefixes** baked into the vendor's own models:
- `updateWindowPanesTransparency`: shapes named `sweethome3d_window_pane*` get transparency 0.5.
- `updateDeformableModelHierarchy`: if all ~18 `sweethome3d_mannequin_*` prefixes (abdomen, chest, pelvis, neck, head, left/right shoulder, arm, elbow, forearm, wrist, hand, hip, thigh, knee, leg, ankle, foot) are present, the mannequin is wired into a deformable hierarchy (used for the "human" furniture that can be posed).
- `replaceMultipleSharedShapes` / `getNormalizedTransformGroup` resolve `sweethome3d_window_mirror`, hinge/rail prefixes, `ModelManager.SUB_TRANSFORMATION_SEPARATOR` and `DEFORMABLE_TRANSFORM_GROUP_SUFFIX`.
- `getAreaOnFloor` and `getFrontArea` derive 2D footprint/doorway-cut-out areas from the 3D model (used by `Room3D` to cut stairwells out of floors and by `Wall3D` to cut door openings from walls).
**OBSERVED** (1847445 ff., 1866068, 1867435)

**Formats not in the online build.** `kmz`/`KMZ` appears **zero** times in `sweethome3d.min.js` even though the German manual states support for "OBJ-, DAE- und 3DS-Format sowie ZIP-Dateien … und KMZ-Dateien" — the KMZ path is a desktop-only feature and the online bundle simply does not ship it. Likewise `createPhoto`/`createPhotos`/`createVideo`/`exportToOBJ` are stubbed (`function(){}` or `dummyDialogView`) in the online JS view factory: the web edition deliberately disables photo/video/OBJ export. **OBSERVED / DOCUMENTED**

### 2.4 Triangulation and geometry generation

**`GeometryInfo3D`** is a direct port of Java3D's `GeometryInfo`. Types: `TRIANGLE_ARRAY` 0, `TRIANGLE_STRIP_ARRAY` 1, `TRIANGLE_FAN_ARRAY` 2, `QUAD_ARRAY` 10, `POLYGON_ARRAY` 20. `getIndexedGeometryArray()` is the single funnel that converts everything to an `IndexedTriangleArray3D`:
- **De-indexing**: if no explicit `coordinatesIndices` is given, it is synthesised. When `generatedNormals` and a positive crease angle are set, index synthesis is **O(n²)** — for each vertex it linearly scans the whole vertex array for `vec3.exactEquals` to weld duplicates. Otherwise it is the trivial identity mapping (every corner is its own vertex, which is what allows flat shading via generated normals).
- **`POLYGON_ARRAY` → `new Triangulator().triangulate(vertices, coordinatesIndices, textureCoordinateIndices, normalIndices, stripCounts, outCoordIndices, outTexIndices, outNormalIndices)`** — the ear-clipping triangulator from `triangulator.min.js`.
- **`QUAD_ARRAY`** is split manually into two triangles per quad: `(0,1,2)` and `(2,3,0)`, with the same expansion for texture and normal indices.
- **`TRIANGLE_STRIP_ARRAY`** is converted with alternating winding (`h+d, h+(d%2?d+2:d+1), h+(d%2?d+1:d+2)`) and **`TRIANGLE_FAN_ARRAY`** as `h, h+d+1, h+d+2`.
- **Normal generation**: `computeNormals(vertices, coordIndices, outNormals, outNormalIndices)` — if `creaseAngle > 0` (default **44°**) it builds a per-vertex linked list of incident face normals, then for each corner sums the normals whose angle to this face's normal is below the crease angle (`atan2(|cross|, dot) < creaseAngle - 0.001`), normalises and writes a distinct normal index per smoothing cluster. With `creaseAngle == 0` (or undefined) it writes one flat normal per face and reuses it when it `exactEquals` the previous one. **OBSERVED** (1718780–1724503)

**`Triangulator`** (`triangulator.min.js`, 34 324 B, carries a Sun Microsystems 2007 BSD-style header next to the Sweet Home 3D GPL header) is the full Sun "ear-clipping with reflex-vertex handling" implementation. Fields: `loops`, `chains`, `points`, `triangles`, `list` (doubly linked `ListNode`), `vertexList`, `reflexVertices`, `numReflex`, `distances`, `heap`, `numHeap`, `numZero`, `polyArea`, `ccwLoop`, `epsilon` (1e-8, `Triangulator.ZERO`). Methods include `triangulate`, `makeLoopHeader`, `insertAfter`, `deleteHook`, `classifyAngles`, `classifyEars`, `isEar`, `isInCone`, `clipEar`, `isPointInTriangle`, `isVertexInTriangle`, `desperate` (fallback when no ear is found), `handleDegeneracies`, `handleSplit`, `handleCrossOver`, `existsCrossOver`, `existsSplit`, `noHashIntersectionExists`, `projectFace`, `projectPoints`, `determineNormal`, `determineOrientation`, `polygonArea`, `windingNumber`, `checkBottleNeck`, `sortDistance`, `initHeap`/`insertIntoHeap`/`dumpOnHeap`/`deleteFromHeap`. In other words: **it handles holes/chains, self-intersections, near-degenerate triangles, and non-planar polygons projected onto a best-fit plane.** **OBSERVED**

**Where the geometry actually comes from.** Almost all built-in scene geometry is *not* loaded from a model file but is generated procedurally in JS from the Java2D-port boolean machinery:
- `Room3D.createRoomGeometries` uses `new java.awt.geom.Area(shape)`, `Area.subtract(otherRoom)`, `Area.intersect`, `Area.getPathIterator(null)` to get the floor polygon minus neighbouring rooms minus staircases, then `getAreaPoints(area, flatness, …)` to extract polygon loops; it then emits `GeometryInfo3D.POLYGON_ARRAY` with `setStripCounts(contourLengths)` and `setTextureCoordinates` and lets the triangulator produce the triangles. **Sub-floor tessellation**: for non-flat floors it tiles the polygon with `subpartSizeUnderLight`-sized `Rectangle2D.Float` squares and intersects each with the room `Area`, emitting one sub-polygon per tile. This is the classic Java3D/desktop `subpartSizeUnderLight` remedy for **per-vertex** lighting; the JS fragment shader is per-fragment, so in the online edition the tessellation is mostly inherited behaviour rather than a necessity.
- `Wall3D.createWallGeometries` builds wall faces by iterating the `Area` path of the wall rectangle minus door/window areas (`Area.subtract(doorOrWindowArea)`), including a two-pass split of overlapping door/window rectangles so the cut-outs do not overlap; then it emits a `QUAD_ARRAY` of vertical quads (from `getWallBottomElevation` to top) and `POLYGON_ARRAY`s for horizontal caps and tops. Trapezoidal walls (arc extent ≠ 0) use `atan2` and arc-circle-centre geometry, and a texture V coordinate that is **arc length in metres**, not normalised UV.
- `HomeComponent3D.createHalfSphereGeometry(sky)` builds the sky/ground hemisphere as an explicit `IndexedTriangleArray3D` with 48 angular segments × 12 vertical bands; the background "ground disc" is a 4-vertex `IndexedTriangleArray3D` with a generated `(0,1,0)` normal.
- `HomePieceOfFurniture3D` falls back to a unit `getModelBox(vec3)` while the model loads and on `modelError`, and uses `IndexedLineArray3D` for the selection box.
**OBSERVED**

**Note on the 2D plan and 3D icons.** `PlanComponent.PieceOfFurnitureModelIcon` creates a **separate offscreen `HTMLCanvas3D`** (size 128, keyed per icon size) with `PARALLEL_PROJECTION`, `frontClipDistance(-1.1)`, `backClipDistance(1.1)`, four directional lights + one ambient light, scales the model by `2/width, 2/depth, 2/height`, renders it, and calls `canvas3D.getImage(callback)` (which does `canvas.toDataURL()` → `new Image()`) to get the icon. ### 2.5 Performance measures the app itself takes

This is the question's core and the app is more deliberate about it than a typical hand-rolled WebGL renderer.

1. **Adaptive texture-download concurrency ("jerk monitor").** `TextureManager` is a singleton (`getInstance()`) with `downloadMinLimit = 2`, `downloadMaxLimit = 12` (8 on Safari, detected by UA regex), and `maxDownloads` starting **well below** those: `3` on Safari / `6` otherwise. `startJerkMonitor()` runs a `requestAnimationFrame` loop that measures inter-frame deltas; every 60 frames it computes `jerkRatio = (frames with delta > 50 ms) / frames`. If `jerkRatio > 0.2` and `maxDownloads > downloadMinLimit` it *decrements* `maxDownloads` and logs `"TextureManager.maxDowload decreased to N"`; if `< 0.05` and below `downloadMaxLimit` it increments. The monitor **stops itself** (`jerkMonitorRunning = false`) as soon as there is nothing active or queued, and restarts on the next load. When `activeDownloads >= maxDownloads`, new image loads are queued and released by `downloadFinished()`. So the concurrency window is a closed-loop, jank-driven throttle that starts conservative, backed off further under jank, and only ramps up when frames are cheap. **OBSERVED** (1852815 ff.)
2. **Coalesced dirty-flag repaint, no render loop.** One `requestAnimationFrame` per invalidation, no continuous `rAF`; `canvasNeededRepaint` guards against re-scheduling. `drawScene()` itself has no animation. Camera moves go through `moveCameraWithAnimation` + a `cameraInterpolator` with an ease alpha, again repainting on demand. **OBSERVED**
3. **FPS measurement that is computed but unused.** `drawScene()` keeps `lastDrawSceneTime`, `previousFramesPerSecondTime`, `drawnFrameCount`, and once per wall-clock second sets `framesPerSecond = round(drawnFrameCount / (now - previousFramesPerSecondTime) * 10000) / 10`; `HTMLCanvas3D.prototype.getFramesPerSecond()` returns it. Grepping the bundle, `getFramesPerSecond` appears **exactly once (its own definition)** — nothing calls it and there is no FPS overlay. **OBSERVED**
4. **Redundant-state elimination.** Every `gl.uniform*` in `drawGeometry` is guarded by `exactEquals` against a cached shader value (`shaderModelViewTransform`, `shaderAmbientColor`, `shaderSpecularColor`, `shaderDiffuseColor`, `shaderNormalTransform`, `shaderShininess`, `shaderAlpha`, `shaderUseTextures`, `shaderLightingEnabled`, `shaderIgnoreNormal`, `shaderBackFaceNormalFlip`, `shaderTextureCoordinatesGenerated`, `shaderTextureTransform`, `shaderCullFace`) — real `glGetUniformLocation`-backed uniform objects, so this is meaningful CPU-side saving rather than a JS-only micro-optimisation. **OBSERVED**
5. **Geometry de-duplication / instancing.** `prepareGeometry` shares draw items across instances of a model when the shape is immutable (`referenceCount`), `ModelManager.load` caches parsed model nodes per URL, `cloneNode` reuses `Link3D` shared groups, and `ModelManager.cloneNode` keeps a `{sharedGroup, clonedSharedGroup}` memo list so a scene with N copies of a model has 1 set of VBOs. Materials/appearances are shared too (`Appearance3D` property-change listeners push edits to all geometries referencing them). **OBSERVED**
6. **Deferred/off-thread-ish work.** Scene binding runs on a `setTimeout(0)` and yields progress every 10 %; multi-entry ZIPs parse one entry per `setTimeout` tick; the save/export path uses a dedicated Web Worker (`recorderworker.min.js`, round 1); texture *decoding* uses the browser's `Image` pipeline. **OBSERVED**
7. **Caches keyed on edit.** `HomeComponent3D` keeps `approximateHomeBoundsCache` and `homeHeightCache`, both invalidated by furniture/wall/room changes and used for camera clipping and "zoom to fit"; `Wall3D.rotatedModelsFrontAreas` caches door cut-out areas per `(model, modelRotation, cutOutShape)`. `HomeComponent3D.updateObjects` **batches** mutations into `homeObjectsToUpdate` and flushes them in one `setTimeout(0)` so a multi-select edit triggers one geometry rebuild per object, not per property change. **OBSERVED**
8. **Picking is a render-to-texture, not a ray cast.** One framebuffer render of pickable geometry with ID colours and one full-buffer `readPixels`; the buffer is cached until an edit invalidates it (`pickingFrameBufferNeededRepaint`). The framebuffer dimensions are rounded up to powers of two, and the mapping from client coordinates uses the live `getBoundingClientRect()`. **OBSERVED**
9. **NPOT textures are resized, not clamped.** Because mipmaps require POT in WebGL 1, the app draws any NPOT image into a POT scratch canvas, converts it with `toDataURL()`, and re-loads it as an `Image` — so the texture upload path can itself cause a visible one-frame delay and a base64 round trip. **OBSERVED**
10. **Clipping and camera scaling.** `HomeComponent3D.updateView` is a small adaptive depth-range policy: FOV defaults to 63° if the camera reports 0; `frontClipDistance` starts at **2.5 cm** and `backClipDistance = front × 500 000`, so the ratio is enormous. If the live context reports `DEPTH_BITS <= 16`, the back clip is cut to **3 000** and the front clip is raised toward `0.1 ×` the distance from the camera to the approximate home-bounds box (a classic 16-bit-depth fix); with 24-bit depth the front clip instead grows with the camera's height above the home (`(z − homeHeight)/10`). Finally, when the camera is above ground and the canvas has a size, it computes the vertical half-FOV and clamps the front clip to `0.35 × z / sin(pitch + halfFov)` so the near plane does not clip the floor the user is looking at. **OBSERVED** — measured `DEPTH_BITS` was 24, so the long-range branch is the live one.

### 2.7 Where the interesting numbers land

The 18 277 draw calls / 1.05 M triangles across 34 active frames over a ~60 s load is a *loading and settling* profile, not a steady-state frame rate: the app re-renders on each asynchronous texture/model arrival, which is why the per-active-frame draw count is so high (520–713). The 2.6 steady-state run separates the two regimes: after ≈13.5 s the scene settles at 18 302 draws, **4 s of idle adds zero draws**, and a single left-button camera drag adds **32 085 draws** — so the cost is *concentrated in interaction*, not in idling or in a background loop. The load-bearing conclusions are structural, not FPS:
- the renderer is **draw-call heavy and batch-poor** (avg ≈57 triangles per `drawArrays`), because de-indexing + per-`Shape3D` draw items;
- it is **idle-efficient** (0 draws while idle; 2 029 of 2 063 frames issued zero draws during loading);
- it is **WebGL 1 with no extension use in its own renderer**, even though the context offers 36 extensions including `OES_element_index_uint`, `OES_vertex_array_object`, `ANGLE_instanced_arrays` and `EXT_disjoint_timer_query` — the 3D view leaves all four on the table. **OBSERVED / INFERRED**

Section 2.5 documents *policies visible in code*; §2.6 gives aggregate counts, settle time and per-interaction draw deltas, but not per-phase milliseconds.
3. **No steady-state FPS on a real GPU.** §2.6 now has a settle point (≈13.5 s), an idle delta (0 draws in 4 s) and drag/zoom draw deltas, but the run was on SwiftShader and the `frames` counter was contaminated by Playwright's own `requestAnimationFrame` polling, so no trustworthy FPS number is claimed.
4. **`MAX_DIRECTIONAL_LIGHT = 16` was read from the source** (`HTMLCanvas3D.MAX_DIRECTIONAL_LIGHT=16`); the runtime light count for a real home was not exercised. `HomeComponent3D.createLights` always emits exactly 4 directional + 1 ambient light, and `HomeLight` bulbs are not converted to scene lights, so the 16-light uniform array is effectively fixed at 4 in practice — the zero-fill branch is almost certainly never hit for the built-in scene lights.
5. **The scene near/far split was not verified by rendering a known test scene.** I confirmed from source that the `0.001`/`1.0` pair belongs to the *background hemisphere* pass (unit-radius dome, camera translation removed) and that the scene pass recomputes the projection via `getVirtualWorldToImageTransform` using `frontClipDistance`/`backClipDistance`; I also captured the `updateView` policy. Whether any z-fighting survives at extreme home scales is still untested. Live `DEPTH_BITS` was 24, so the 16-bit branch was not taken.
6. **Which component built the second `HTMLCanvas3D` was not attributed.** `shadersCompiled: 4` / `programsLinked: 2` implies exactly two renderer instances existed, but the instrumentation only captured the first `getContext` call (the id-less capability-probe canvas). The second is most likely the offscreen furniture-icon renderer, but I did not tag each `new HTMLCanvas3D` call site live to prove it.
7. **The 3DS parser's exact coverage is not exhaustively verified.** I read the chunk table and the node/pivot handling, but did not feed it a diverse corpus of `.3ds` files (key-framed, multi-material, smoothed). Behaviours for exotic chunks are **INFERRED** from constants.
8. **DAE skinning is only partly understood.** The handler tracks `controllersSkinMeshes` and the changelog mentions MakeHuman, but I did not verify how skin/joint matrices become `TransformGroup3D`s at runtime, nor whether inverse-bind matrices are applied. This matters only if CasaPlazAI ever imports rigged models.
9. **The picking path was never exercised live** (`readPixels: 0`, `framebuffers: 0`) even after synthetic hover/click/move — injected canvas events did not reach the app's picking handler, matching round 1's lesson (b). The pick-framebuffer description in 2.2 is therefore source-verified only; a real user click in 3D (or a page-exposed picking API call, if one exists) would be needed to confirm the ID encoding and buffer-reuse policy empirically.
10. **The service-worker `resourceCache.js` behaviour itself was still not exercised** (round 1's Unknown #6). This session only proved *why* it blocked Playwright — the forced `window.location.reload()` when `navigator.serviceWorker.controller` is null. Its actual caching of `/online/readResource.jsp` responses remains unobserved; in the live run all 872 asset requests hit the local proxy with status 200.
11. **Third-party scripts were stripped in the live run**, so the measured page is the app core *without* GTM/iubenda/Firebase. This is intentional (they reload the document) and does not affect the 3D pipeline, but the measured page is not byte-identical to the production document. All app scripts (`/libjs/*`, `/examples/*`, `/models/*`) were served unmodified from the live origin through the proxy.
12. **`getFramesPerSecond` really is dead code** is asserted from a whole-file grep (exactly 1 occurrence). It is theoretically possible it is invoked through a computed string in the bundle. Confidence high, not absolute.
13. **Licence boundary (unchanged).** Sweet Home 3D is GPL-2.0+; `triangulator.min.js` carries an additional Sun 2007 BSD-style notice. Nothing was copied; every idea in §3 is behaviour-level. But the ear-clipping *algorithm* is not the transferable part — the transferable parts are the caching, throttling, batching and instancing policies, which are generic.
